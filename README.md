# 图像搜索系统

一个基于深度学习和向量检索的图像搜索系统，采用粗排到精排的两阶段匹配策略，使用Milvus作为向量数据库存储和检索图像特征。

## 项目特点

- **目标检测与裁剪**：上传的图片先经过自定义数据集yoyo8训练的模型进行目标检测和裁剪，提取出搜索目标
- **粗排到精排策略**：先使用全局特征进行快速筛选（粗排），再使用patch-level特征进行精细匹配（精排）
- **高效向量检索**：使用Milvus向量数据库进行快速相似度搜索
- **电商家具搜索**：专门针对家具商品优化的特征提取和匹配算法
- **前端界面**：提供直观的图像上传和搜索结果展示界面

## 技术栈

- **深度学习框架**: PyTorch
- **目标检测模型**: 基于自定义数据集yoyo8训练的目标检测模型
- **图像特征提取**: Trendyol DINOv2 E-commerce模型 (256维特征)
- **向量数据库**: Milvus
- **后端服务**: Flask
- **前端界面**: HTML/CSS/JavaScript
- **特征匹配**: ArcFace + Triplet Loss

## 项目架构

1. **目标检测与裁剪阶段**
   - 上传的图片首先进入目标检测模块
   - 使用基于自定义数据集yoyo8训练的模型进行目标检测
   - 自动裁剪出图像中的目标搜索物
   - 输出裁剪后的目标图像用于后续处理
   - 此阶段确保只对图像中的目标物体进行特征提取，提高搜索准确性
   - 当前实现中，目标检测模块需要在`scripts/port.py`的`image_search`函数中集成

2. **特征提取阶段**
   - 使用Trendyol DINOv2 E-commerce模型提取图像特征
   - 提取256维全局特征用于粗排
   - 提取patch-level特征用于精排

3. **向量存储与检索阶段**
   - 使用Milvus向量数据库存储图像特征
   - 支持高效的相似度搜索

4. **粗排到精排阶段**
   - 粗排：使用全局特征快速筛选候选
   - 精排：使用patch特征进行精细匹配

## 使用说明

### 1. 安装依赖和启动Milvus服务

```bash
pip install -r requirements.txt
```

确保Milvus服务运行在`127.0.0.1:19530`

### 2. 准备yoyo8目标检测模型

- 确保已训练好基于yoyo8数据集的目标检测模型
- 将模型文件放置在项目相应目录（如 `./models/yolo8/`）
- 在代码中配置目标检测模块以使用该模型进行图像裁剪
- 验证目标检测模型能够正确识别和裁剪图像中的目标物体
- 在 `scripts/port.py` 文件中的 `image_search` 函数中集成目标检测预处理步骤

### 3. 训练特征提取模型

```bash
cd feat
python train_trendyol.py
```

该脚本将：
- 使用`./data`目录中的家具图像数据进行训练
- 采用Triplet Loss + ArcFace的组合损失函数
- 仅微调模型的最后几层以平衡性能和稳定性
- 保存训练好的模型到`./checkpoints_hard/`

### 3. 提取并插入特征

```bash
cd scripts
python insert_features.py
```

该脚本将：
- 从`./datasets/new_goods`目录读取图像
- 提取全局特征和patch-level特征
- 将特征存储到Milvus向量数据库
- 同时保存patch特征到本地`./patch_store/`目录

### 4. 启动后端服务

```bash
cd scripts
python port.py
```

服务将在`http://127.0.0.1:5000`启动

### 5. 使用前端界面

打开`index.html`文件，通过浏览器界面上传图片并搜索相似图像

## 训练说明

### 目标检测模型训练（yoyo8数据集）

- 使用自定义的yoyo8数据集训练目标检测模型
- 模型用于自动检测和裁剪图像中的目标搜索物
- 输出裁剪后的目标区域用于特征提取

### 特征提取模型训练

#### 数据准备

- 将训练数据放在`./data`目录下
- 每个商品放在独立的文件夹中
- 每个商品文件夹中至少包含2张图像

#### 训练配置

- **模型**: Trendyol/trendyol-dino-v2-ecommerce-256d
- **优化器**: AdamW
- **学习率**: 1e-4 (余弦退火调度)
- **损失函数**: Triplet Margin Loss + ArcFace Loss
- **Batch Size**: 32
- **Epochs**: 30

### 微调策略

- **方案A（推荐）**: 仅微调`fc11`和`bn11`层（适合小数据集）
- **方案B（增强）**: 微调backbone最后2-3层 + `fc11` + `bn11`（适合大数据集）

### 模型输出

- **全局特征**: 256维向量，用于粗排
- **Patch特征**: [N, 768]维向量，用于精排

## 粗排到精排流程

### 1. 粗排阶段

- 使用256维全局特征进行快速相似度计算
- 采用余弦相似度进行匹配
- 从大量候选中筛选出前K个候选

### 2. 精排阶段

- 使用patch-level特征进行细粒度匹配
- 支持cross-attention机制
- 组合全局和局部特征（默认权重：全局0.7，patch 0.3）

### 3. 特征提取

- **全局特征**: 模型最终输出的归一化256维向量
- **Patch特征**: 通过hook获取的中间层特征（257×768，256个patch + 1个cls token）

## 性能优化

- **向量索引**: 使用IVF_FLAT索引提高检索效率
- **批处理**: 特征插入支持批量处理
- **缓存机制**: 特征缓存减少重复计算
- **分层检索**: 粗排快速过滤，减少精排计算量

## 评估指标

- **特征提取时间**: 提取单张图像特征的耗时
- **向量检索时间**: 在Milvus中搜索的耗时
- **总响应时间**: 从上传图像到返回结果的总耗时
